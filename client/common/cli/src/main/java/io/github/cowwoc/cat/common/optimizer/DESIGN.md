# Prompt Optimizer Design Record

## Purpose and authority

This is the maintainer record for the optimizer being built under the project-root `frontend.md` product contract and
`frontend-implementation.md` execution plan. It records accepted choices and the evidence needed to accept their
implementation. The product contract decides observable behavior; the plan assigns components, handoffs, and gates.
This record does not turn a planned check into a passed check. W0 seeds the accepted choices below; the owner of each
later slice records any further design choice before closing that slice. W8 reconciles this record with the integrated
product. Superseded decisions belong in dated implementation receipts, not in this current decision list.

implementation owner or handoff, and the acceptance evidence. A referenced gate is required evidence, not a claim that
the gate has passed.

## Generation authority and cost

The selected generation design uses prompt restrictions, measured adherence, existing runner isolation, staged external
targets, and complete no-follow inventory validation before candidate or trial admission. A forbidden observed
operation or final delta rejects the whole attempt; no custom filesystem, FUSE dependency, or additional process
sandbox is selected. The user requested allowed accepted edits and isolation of selected/base worktrees and live
external targets. Preventing every temporary symlink or mode change would strengthen that outcome with native
implementation, platform, lifecycle, and verification costs. Failure likelihood remains unknown until measured.
Disposable attempt edits can be inspected and reconciled for retry; Git diff and undo alone do not cover external
content, untracked files, or all permissions. Existing live-target isolation remains necessary. Transient forbidden
changes reverted before inspection may escape detection when no operation event exposes them. P2 checks both installed
harnesses, prompt-adherence counts, unchanged live destinations, and injected forbidden-delta rejection. H4/H8/H10
retain exact allowed-snapshot and delivery checks. W4 remains open until that revised behavior is demonstrated.
